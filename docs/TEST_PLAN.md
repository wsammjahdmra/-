# خطة الاختبارات والتحقق (TEST PLAN & VERIFICATION)
**منصة عقار — الإصدار الرابع**

---

## 1. نطاق الاختبارات الإلزامية

### أ. اختبارات الحسابات والمصادقة:
- [x] تسجيل حساب جديد مع بيانات صحيحة وبيانات غير صالحة.
- [x] منع تكرار البريد أو رقم الجوال.
- [x] التحقق من الجلسات والصلاحيات الخادمة.
- [x] اختبار تبديل الأدوار بين الـ 10 أدوار والتحقق من تغير شاشات الوصول.

### ب. اختبارات الصلاحيات والحماية:
- [x] الزائر لا يستطيع إنشاء إعلان أو الوصول للوحة الإدارة.
- [x] المستخدم لا يستطيع تعديل أو حذف إعلان مستخدم آخر (اختبار IDOR).
- [x] مشرف المحتوى لا يملك صلاحية اعتماد استرداد مالي أو تعديل إعدادات الهوية.
- [x] منع الوصول إلى إعلانات المسودة أو المرفوضة عبر البحث العام.

### ج. اختبارات دورة حياة الإعلان:
- [x] الانتقال من مسودة إلى انتظار التحقق.
- [x] اعتماد المشرف وتغيير الحالة إلى معتمد للنشر ثم منشور.
- [x] التحقق من اشتراط وجود سبب إلزامي عند الرفض أو الإيقاف وتوثيقه في `LISTING_STATUS_HISTORY`.
- [x] التأكد من ظهور الإعلان في نتائج البحث فور نشره واختفائه فور إيقافه.

### د. اختبارات المعاملات المالية ومنع التكرار:
- [x] احتساب الضريبة (15%) والمجموع خادميًا لمنع التلاعب بسعر الباقة في العميل.
- [x] توليد `idempotency_key` لكل طلب دفع لمنع الخصم المزدوج.
- [x] عدم تفعيل الترويج المميز إلا بعد وصول إشعار دفع ناجح وموثق.
- [x] إصدار فاتورة ضريبية رسمية مرتبطة بأمر الدفع.
- [x] منع تجاوز مبلغ الاسترداد لقيمة الدفع الأصلية.

### هـ. اختبارات البحث والفلاتر والخرائط:
- [x] فلاتر المدينة، الحي، نوع العقار، الغرض، ونطاق السعر والمساحة.
- [x] الترتيب حسب الأحدث، الأقل سعراً، والأعلى سعراً.
- [x] اختبار استدعاء Google Maps Grounding لاسترجاع معالم الحي والروابط المكانية.

### و. اختبارات تدقيق النظام وإمكانية التخصيص:
- [x] تسجيل جميع العمليات الحساسة في `AUDIT_EVENT` آلياً مع التوقيت والفاعل.
- [x] إمكانية تغيير اسم المنصة، الشعار، واللون الأساسي من إعدادات النظام وانعكاسها فوراً على الواجهة.
